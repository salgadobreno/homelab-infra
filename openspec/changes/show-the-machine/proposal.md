## Why

Everything this project has built is legible only by reading the repository. The public
site is a CV that happens to be served by a Kubernetes cluster, and nothing about it says
so.

This is the rung that shows the work to someone who will not read the repo. It is also
the first thing built here whose audience is not the operator.

There is a hand-drawn diagram already in this repository showing `microk8s`, `ansible` and
a host called `buserver`. None of them exist. It was accurate once, which is the whole
argument: a picture that can disagree with reality eventually will, and a self-describing
site that lies is worse than one that says nothing.

## What Changes

- **The site gains a section describing the infrastructure serving it** — nodes,
  workloads, what ArgoCD last synced and from which revision, and the shape of the path a
  request takes.
- **`make diagram` generates that section** from the cluster's own output. It is static
  content, committed like any other page — not rendered at request time, with nothing in
  the cluster reading the API.
- **`make check` fails when the committed page disagrees with the cluster**, so drift is
  a failing check with a one-command fix rather than something noticed years later.
- **A disclosure boundary is written down and enforced**: shapes, versions, counts and
  sync state are published; addresses, storage paths and account names are not.
- **The page shows both halves** — what runs now, and the Compose-on-the-hypervisor
  arrangement it replaced. The delta is the point; the current state alone does not say
  what was learned.
- **`k8s/site/content/diagram.ascii` is deleted**, because it is the thing this rung
  exists to make impossible.

Explicitly **not** in this change:

- A runtime renderer. An earlier draft of this proposal had a sidecar querying the
  Kubernetes API, which came from reading "generated" as "generated at request time". It
  is generated by a command and committed. That mistake cost an RBAC surface and a
  runtime dependency on a page that changes a few times a month.
- A dashboard, metrics, or history. That is M7.
- Owning the whole page. This content later becomes a section of the operator's personal
  site, so it is built as a fragment that could be embedded.

## Capabilities

### New Capabilities

- `infrastructure/self-description`: the public site describes its own infrastructure from
  the cluster's own output, within a stated disclosure boundary, and cannot quietly
  disagree with what is running.

### Modified Capabilities

None. `site-delivery` already requires the cluster to serve the site; this adds what the
site says, not how it is delivered.

## Impact

- **The public site's content.** Every previous change moved where the site was served
  from. This is the first that changes what a visitor sees.
- **`make check`** gains an assertion that can fail because the world changed rather than
  because the repository did — the first check here with that property.
- **A generator script**, which is the first thing in this repo whose output is committed
  rather than applied. Its determinism matters: a generator whose output varies run to run
  makes the drift check cry wolf.
